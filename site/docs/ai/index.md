# 模型提供商

从 **v1.0.0** 开始，Kaloscope 支持统一接入云端或本地大模型，供[内置助手](./assistant)和工作流中的 [AI 节点](../workflows/ai)调用。如果不打算用 AI，现有的搜索、下载、媒体库和工作流功能照常可用，不受影响。

## 添加提供商

管理员可以在 **设置 → 系统设置 → 模型提供商** 中选择常见预设，或选「自定义提供商」手动填写连接信息：

| 字段     | 说明                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 名称     | 用来区分不同连接的显示名称，同一服务也可以建多个连接                                 |
| API 地址 | 模型服务的基础地址；需要带版本号的路径（如 `/v1`）请一并填上，但不要包含 `/chat/completions` |
| API Key  | 访问密钥；不需要鉴权的本地模型服务留空即可                                           |
| 模型     | 可以点「获取模型」自动拉取后选择，也可以手动填入模型 ID（每行一个，最多 100 个）     |
| 已启用   | 关闭后，助手和 AI 节点将无法再使用这个连接                                           |

保存前建议点一下「测试连接」。不过要注意，它只检查模型列表接口是否通畅，并不检验生成回复的能力，也无法判断某个模型是否支持工具调用或结构化输出。如果所用服务不提供模型列表接口，直接手动填好模型 ID 保存，再通过实际调用验证即可。

## 接口兼容性

目前 Kaloscope 统一通过 **OpenAI 兼容的 Chat Completions 接口**请求模型。系统内置的 OpenAI、Anthropic、Gemini、xAI、DeepSeek、OpenRouter、Ollama 和 LM Studio 等预设，只是帮你预先填好默认地址，内容都可以自行修改。

也就是说，所接的服务必须提供兼容接口——如果某个地址只支持自家原生协议，光选同名预设是调不通的，需要换成可用的兼容接口地址。另外，[AI 助手](./assistant)要求模型支持**工具调用**，工作流里的 [AI 节点](../workflows/ai)则按任务选择纯文本或结构化输出能力。

## 连接本地模型

Ollama 和 LM Studio 预设默认填的是 `http://127.0.0.1:11434/v1` 和 `http://127.0.0.1:1234/v1`，请按 Kaloscope 的实际运行位置修改：

| 部署方式                                   | 地址示例                               |
| ------------------------------------------ | -------------------------------------- |
| Kaloscope 与模型服务均直接运行在同一宿主机 | `http://127.0.0.1:11434/v1`            |
| Kaloscope 在 Docker 中，模型服务在宿主机   | `http://host.docker.internal:11434/v1` |
| 两者位于同一 Docker 网络                   | `http://<模型服务名称>:11434/v1`       |

在 Docker 容器里，`127.0.0.1` 指的是容器自己，而不是宿主机。[本地部署示例](../deployment)里已经配好了 `host.docker.internal` 映射；同时别忘了让宿主机上的模型服务监听容器可访问的地址，并放行对应网络连接。

## 常见问题与修改

- 编辑已有连接且不改 API 地址时，API Key 留空会沿用原有密钥；修改 API 地址后需要重新填密钥，无需鉴权时留空即可清除旧密钥
- 停用或删掉某个提供商，或者从列表中移除某个模型后，记得去助手或相关的 AI 节点里重新选定模型
- 遇到认证失败时，优先核对密钥和账户里的模型权限；如果总是超时或连不上，排查服务地址、防火墙以及[网络设置](../network)里的代理规则
- 如果助手无法调用工具，先确认所选模型本身以及兼容服务都支持工具调用

配好模型后，就能打开[内置助手](./assistant)开始对话，或在工作流里加入 [AI 节点](../workflows/ai)。如果想用外部 AI 客户端连接 Kaloscope，请看 [MCP 接入](./mcp)，用外部客户端无需先配置这里的模型提供商。
