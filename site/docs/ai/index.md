# 模型提供商

从 **v1.0.0** 开始，Kaloscope 可以统一配置云端与本地模型，供[内置助手](./assistant)和 [AI 工作流节点](../workflows/ai)使用。未配置模型时，原有搜索、下载、媒体库与工作流功能仍可正常使用。

## 添加提供商

管理员进入**设置 → 系统设置 → 模型提供商**，选择预设或「自定义提供商」，填写连接信息：

| 字段     | 说明                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 名称     | 用于区分连接的显示名称，可以为同一服务创建多个连接                      |
| API 地址 | 模型服务的基础地址，按需包含 API 版本路径，不要填写 `/chat/completions` |
| API Key  | 模型服务的访问密钥；无需认证的本地服务可留空                            |
| 模型     | 点击「获取模型」后选择，或手动填写模型 ID，每行一个，最多 100 个        |
| 已启用   | 停用后，助手和 AI 节点不能继续使用该连接                                |

保存前可点击「测试连接」。此操作检查模型列表接口是否可访问，不会实际生成回复，也不代表列表中的每个模型都支持工具调用或结构化输出。模型列表接口不可用时，可以手动填写模型 ID，再通过实际调用验证。

## 接口兼容性

当前模型调用使用 **OpenAI 兼容的 Chat Completions 接口**。预设包括 OpenAI、Anthropic、Gemini、xAI、DeepSeek、OpenRouter、Ollama 和 LM Studio，预设只是可编辑的连接默认值。

模型服务必须提供兼容接口。仅支持其他原生协议的地址，不能仅靠选择同名预设直接调用；需要改为可用的兼容地址。助手还要求模型支持**工具调用**，AI 节点则按任务选择文本或结构化输出能力。

## 连接本地模型

Ollama 和 LM Studio 预设分别使用 `http://127.0.0.1:11434/v1` 和 `http://127.0.0.1:1234/v1`。请根据 Kaloscope 实际运行位置修改：

| 部署方式                                   | 地址示例                               |
| ------------------------------------------ | -------------------------------------- |
| Kaloscope 与模型服务均直接运行在同一宿主机 | `http://127.0.0.1:11434/v1`            |
| Kaloscope 在 Docker 中，模型服务在宿主机   | `http://host.docker.internal:11434/v1` |
| 两者位于同一 Docker 网络                   | `http://<模型服务名称>:11434/v1`       |

Docker 中的 `127.0.0.1` 指向 Kaloscope 容器自身。[部署示例](../deployment)已添加 `host.docker.internal` 映射；模型服务仍需监听容器可访问的地址，并允许对应网络连接。

## 修改与排错

- 编辑同一地址时，API Key 留空会保留原密钥；修改 API 地址后需重新填写密钥，或在无需认证时留空清除原密钥
- 停用、删除提供商，或移除已使用的模型后，需要在助手或相关 AI 节点中重新选择
- 认证失败时检查密钥和模型权限；超时或连接失败时检查服务地址、网络规则和代理配置
- 助手无法调用工具时，先确认所选模型及兼容服务支持工具调用

后续可[打开助手](./assistant)处理日常任务，也可在工作流中加入 [AI 节点](../workflows/ai)。外部 AI 客户端的连接方式见 [MCP 接入](./mcp)，无需先配置内置模型提供商。
