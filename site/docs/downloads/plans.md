# 下载计划

下载计划专门用来自动追更。设好搜索工作流、过滤条件和间隔时间后，系统就会按时扫一遍新资源，把命中的条目自动送进下载器，省去隔三差五手动重搜的麻烦。

## 新增计划

在**下载计划**页面点击右上角「新增下载计划」，按需填写这些选项：

| 字段       | 必填 | 说明                                                               |
| ---------- | ---- | ------------------------------------------------------------------ |
| 工作流     | ✓    | 绑定一个已发布的「网络搜索」工作流，创建后不可更换                 |
| 关键词     |      | 传入工作流的搜索关键词；是否必填取决于搜索链路里的配置             |
| 附加筛选   |      | 来自工作流搜索配置的额外筛选条件，如分辨率、字幕语言等             |
| 间隔       | ✓    | 计划执行的间隔时间，单位为小时                                     |
| 开始时间   |      | 计划的最早触发时间，留空则保存后立即生效                           |
| 结束时间   |      | 计划的最晚触发时间，留空则不限制结束                               |
| 单次上限   | ✓    | 每次执行最多提交的下载数量                                         |
| 总上限     |      | 计划累计提交的最大下载数量，达到后自动停止                         |
| 下载器     | ✓    | 命中资源后交给哪个下载器去下                                       |
| 保存到     | ✓    | 下载文件在下载器端的保存路径                                       |
| 完成后转移 |      | 下载完成后自动将文件转移到指定媒体库（规则见下方说明）             |

## 通过助手管理计划

你也可以直接让 [AI 助手](../ai/assistant)帮忙创建、修改或删除计划。新建前它会先扫一遍现有的媒体库和已有计划，提醒你有没有重复追更的风险，并把搜索结果、过滤条件、保存路径和转移预览列出来，确认后再提交。注意如果没填开始时间，计划刚建好就可能立刻跑第一次搜索，建好了也不代表一定马上下完了。

修改计划时，助手会列出改动前后的对比；如果搜索条件变了，还会重新搜一遍给你预览。删掉计划本身不会把之前已经下好的任务和文件删掉，也不会打断正在运行的那一轮执行。

## 完成后转移

如果配置了**转移目标媒体库**，文件下完后就会转移到目标媒体库根目录（或按下面规则替换后的相对路径）下，并触发入库流程。

| 字段       | 必填 | 说明                                                           |
| ---------- | ---- | -------------------------------------------------------------- |
| 目标媒体库 | ✓    | 文件转移的目标媒体库                                           |
| 转移方式   | ✓    | 文件迁移方式：`硬链接`、`软链接`、`移动`或`复制`               |
| 正则表达式 |      | 用于匹配原始下载文件名（相对于下载目录的保存路径）的正则表达式 |
| 替换字符串 |      | 替换结果，支持正则捕获组引用（如 `\1`、`\2`）和 Jinja2 模板    |

**文件名替换示例：**

| 正则表达式           | 替换字符串 | 原文件名                     | 结果文件名        |
| -------------------- | ---------- | ---------------------------- | ----------------- |
| `\[.*?\]\s*`         | （空）     | `[SubGroup] Show S01E01.mkv` | `Show S01E01.mkv` |
| `\s*\[.*?\](\.\w+)$` | `\1`       | `Show S01E01 [1080p].mkv`    | `Show S01E01.mkv` |
| `^(.+/)?`            | `Show/`    | `[SubGroup] Show/S01E01.mkv` | `Show/S01E01.mkv` |

上表里的表达式直接按原样填进界面就行，不需要像 JSON 字符串那样再多转义一层反斜杠。

替换字符串里还可以使用 Jinja2 模板，系统会从**当前文件名**里提取出 `title`、`year`、`season`、`episode` 这几个变量给你用。遇到多文件任务时，每个文件都会各自提取、单独渲染，不会全都套用第一个文件的集数；不过要分清，这里提取的信息来自下载文件名本身，跟后续通过 NFO 刮削出来的正式元数据不同。替换后如果同一任务内出现重复目标名，系统会放弃这组替换并保留原相对路径。

::: tip 转移方式
硬链接要求下载目录和媒体库位于同一文件系统（同盘/同挂载点），既能保留源文件做种，又不会多占一份空间；软链接可以跨盘，但前提是原下载文件必须一直留在原位有效；移动会移走原下载文件；复制则会额外占一份空间。
:::

## 转移后自动整理

如果目标媒体库同时配了[自动重命名模板](../medialibs/organization)，整个入库会分两步走：下载完成后先按这里设置的转移方式和文件名替换规则把文件放进媒体库，入库刮削拿到准确的 NFO 元数据后，再按媒体库模板整理成最终的目录和文件名。因此下载阶段适合去掉发布组前缀或安排初步目录，媒体库模板则用来按准确的作品标题、年份和季集信息统一命名。

系统会记录已完成转移的目标路径，哪怕中途中断，重启后也会接着处理剩下的部分。而且只要同一批下载文件还有没转移完的，自动整理就会先等等，避免边转移边挪动目标目录。
