# 下载计划

下载计划用于自动追更。系统会按设定周期执行搜索工作流，把命中的资源自动送入下载器，减少重复手动搜索。

- 绑定一个可用于搜索的工作流
- 指定下载器、保存目录和搜索关键词
- 周期性执行搜索，并把结果自动加入下载器
- 记录最近执行时间、累计命中数量和运行状态

## 新增计划

在**下载计划**页面点击右上角「新增下载计划」，填写以下字段：

| 字段       | 必填 | 说明                                                               |
| ---------- | ---- | ------------------------------------------------------------------ |
| 工作流     | ✓    | 绑定一个「网络搜索」类别的工作流，用于定期执行搜索，创建后不可修改 |
| 关键词     |      | 传入工作流的搜索关键词；是否必填取决于搜索链路配置                 |
| 附加筛选   |      | 来自工作流搜索配置的额外筛选条件，如分辨率、字幕语言等             |
| 间隔       | ✓    | 计划触发的时间间隔，单位为小时                                     |
| 开始时间   |      | 计划的最早触发时间，留空则立即生效                                 |
| 结束时间   |      | 计划的最晚触发时间，留空则不限制结束                               |
| 单次上限   | ✓    | 每次执行最多提交的下载数量                                         |
| 总上限     |      | 计划累计提交的最大下载数量，达到后自动停止                         |
| 下载器     | ✓    | 将搜索结果提交到的目标下载器                                       |
| 保存到     | ✓    | 下载文件的保存路径                                                 |
| 完成后转移 |      | 下载完成后将文件转移到指定媒体库（见下方说明）                     |

## 通过助手管理计划

也可以让 [AI 助手](../ai/assistant)协助创建、修改或删除计划。创建前会检查已有媒体和计划，提示潜在重复，并展示搜索结果、过滤条件、下载位置及转移预览；确认后才会提交。已立即生效的计划可能马上触发搜索和下载，创建成功不表示下载成功。

修改计划时，助手会展示变更前后差异，搜索条件变化时还会重新搜索预览。删除计划会保留已有任务和文件，也不会取消正在进行的执行。

## 完成后转移

如果为计划配置了**转移目标媒体库**，文件下载完成后会转移到媒体库根目录或替换后的相对路径下，并触发入库流程。

| 字段       | 必填 | 说明                                                           |
| ---------- | ---- | -------------------------------------------------------------- |
| 目标媒体库 | ✓    | 文件转移的目标媒体库                                           |
| 转移方式   | ✓    | 文件的迁移方式：`硬链接`、`软链接`、`移动`或`复制`             |
| 正则表达式 |      | 用于匹配原始下载文件名（相对于下载目录的保存路径）的正则表达式 |
| 替换字符串 |      | 替换结果，支持正则捕获组引用（如 `\1`、`\2`）和 Jinja2 模板    |

**文件名替换示例：**

| 正则表达式           | 替换字符串 | 原文件名                     | 结果文件名        |
| -------------------- | ---------- | ---------------------------- | ----------------- |
| `\[.*?\]\s*`         | （空）     | `[SubGroup] Show S01E01.mkv` | `Show S01E01.mkv` |
| `\s*\[.*?\](\.\w+)$` | `\1`       | `Show S01E01 [1080p].mkv`    | `Show S01E01.mkv` |
| `^(.+/)?`            | `Show/`    | `[SubGroup] Show/S01E01.mkv` | `Show/S01E01.mkv` |

上表中的表达式直接填写在界面中即可，不需要像 JSON 字符串那样再次转义反斜杠。

替换字符串还可使用 Jinja2 模板，变量 `title`、`year`、`season`、`episode` 从**当前文件名**提取。多文件任务会逐个文件渲染，不会共用第一个文件的集数；这些值来自下载文件名，与后续 NFO 刮削得到的元数据不同。替换后若同一任务内出现重复目标名称，系统会放弃这组替换并保留原相对路径。

::: tip 转移方式
硬链接要求源文件和目标目录位于同一文件系统，可保留下载源且不复制视频内容。软链接可指向其他卷，但原文件路径必须一直有效；移动会移走原下载文件，复制则会额外占用空间。
:::

## 转移后自动整理

如果目标媒体库配置了[自动重命名模板](../medialibs/organization)，下载文件会先按本页规则转移，入库后再根据 NFO 整理为最终目录和文件名。下载阶段适合去掉发布组前缀或安排初始目录，媒体库模板适合使用准确的作品标题、年份和季集信息统一命名。

系统会记录已完成转移的目标路径，并在中断后继续处理未完成部分。相关下载文件尚未全部转移时，自动整理会延后，避免边转移边移动目标目录。
