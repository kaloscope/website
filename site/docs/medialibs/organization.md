# 自动整理

自动整理根据元数据和媒体库的「自动重命名模板」，调整库内目录与文件名。影视库从 **v0.11.0** 开始支持，[小说与漫画](./reading)从 **v0.12.0** 开始支持，分别读取 NFO、OPF 或 ComicInfo 元数据。

## 开启方式

1. 在**设置 → 系统设置 → 媒体库管理**中新增或编辑媒体库
2. 填写「自动重命名模板」并保存；留空则关闭后续自动整理
3. 确保媒体具有对应类型的元数据，或绑定「资源入库」工作流生成元数据
4. 新媒体入库、元数据被发现或更新、手动刮削保存后，系统会尝试整理对应条目

保存模板本身不会立即整理全部已有文件。已有条目可通过重新刮削或更新元数据触发整理；普通扫描只处理发现的变化，不会强制重处理未变化的元数据。清空模板也不会把已整理的文件还原为旧名称。

## 模板规则

模板填写相对于媒体库根目录的路径，以 `/` 分隔目录，最后一段是**不含扩展名**的正文文件名或阅读单元目录名。系统保留原正文扩展名；独立图片漫画的页面文件名保持不变。

| 媒体库类型 | 支持的结构                                    |
| ---------- | --------------------------------------------- |
| 电影       | `文件名` 或 `电影目录/文件名`                 |
| 电视剧     | `剧集目录/文件名` 或 `剧集目录/季目录/文件名` |
| 小说、漫画 | `作品目录/阅读单元名`，必须正好两段           |

::: v-pre
模板只支持下表中的 `{{字段名}}` 占位符和普通文本，不支持工作流中的 Jinja2 过滤器、条件或表达式。例如 `{{season}}` 可用，`{{season | default(1)}}` 不可用。
:::

模板不能使用绝对路径、空目录段、`.`、`..` 或反斜杠，最长为 1024 个字符。元数据里的路径分隔符和非法文件名字符会被替换成下划线；单个渲染后的目录名或文件名主体不能超过 240 个 UTF-8 字节。

### 可用字段

::: v-pre

| 字段                       | 含义与使用范围                                                                |
| -------------------------- | ----------------------------------------------------------------------------- |
| `{{title}}`                | 电影标题或单集标题；电视剧中只能用于文件名                                    |
| `{{originaltitle}}`        | 电影或单集的原始标题；电视剧中只能用于文件名                                  |
| `{{year}}`                 | 当前 NFO 的年份；单集缺失时可继承父级年份                                     |
| `{{parent.title}}`         | 父级剧集或季度的标题                                                          |
| `{{parent.originaltitle}}` | 父级 NFO 的原始标题，缺失时不会自动用普通标题替代                             |
| `{{parent.year}}`          | 父级剧集的年份                                                                |
| `{{season}}`               | 季数，仅电视剧可用，自动补齐至少两位，如 `01`                                 |
| `{{episode}}`              | 集数，仅电视剧文件名可用，自动补齐至少两位，如 `03`                           |
| `{{code}}`                 | 季集编号，如 `S01E03`，仅电视剧文件名可用                                     |
| `{{id}}`                   | 当前 NFO 中默认的媒体标识；电视剧目录部分使用父级标识，文件名部分使用单集标识 |
| `{{site}}`                 | 默认媒体标识的来源，如 `tmdb`；单集缺失时可继承父级来源                       |

:::

只在模板中引用实际存在的字段。电视剧目录部分不能使用单集的标题、原始标题、集数或季集编号，避免同一季被拆进不同的单集目录。

旧模板中的 `show_title`、`show_originaltitle`、`show_year`、`episode_code`、`unique_id` 和 `nfo_source` 仍兼容，分别对应 `parent.title`、`parent.originaltitle`、`parent.year`、`code`、`id` 和 `site`。

### 小说与漫画字段

::: v-pre

| 字段                                                              | 含义与使用范围                               |
| ----------------------------------------------------------------- | -------------------------------------------- |
| `{{title}}`、`{{originaltitle}}`                                  | 当前阅读单元的标题、原始标题，只能用于第二段 |
| `{{parent.title}}`、`{{parent.originaltitle}}`、`{{parent.year}}` | 合集或独立作品的标题、原始标题、年份         |
| `{{year}}`                                                        | 出版年份                                     |
| `{{authors}}`、`{{illustrators}}`                                 | 作者、绘者，多人使用逗号连接                 |
| `{{publisher}}`、`{{series}}`                                     | 出版社、系列                                 |
| `{{volume}}`、`{{number}}`                                        | 卷号、话号，不自动补零                       |

:::

第一段使用合集或独立作品的元数据，不能用章节自身的 `title`、`originaltitle`。第二段使用当前阅读单元的元数据，`parent.*` 始终指向该合集或独立作品。阅读模板不支持影视专用的季集编号和 NFO 标识字段。

### 电影示例

```text
{{title}} ({{year}})/{{title}} ({{year}})
```

如果 NFO 标题为「示例电影」、年份为 `2024`，视频扩展名为 `.mkv`，整理结果为：

```text
Movies/
└── 示例电影 (2024)/
    ├── 示例电影 (2024).mkv
    ├── 示例电影 (2024).nfo
    └── 示例电影 (2024).zh-CN.srt
```

### 电视剧示例

```text
{{parent.title}}/S{{season}}/{{code}}
```

如果剧集标题为「示例剧集」、季数为 `1`、集数为 `3`，结果为：

```text
Shows/
└── 示例剧集/
    └── S01/
        ├── S01.nfo
        ├── S01E03.mkv
        ├── S01E03.nfo
        └── S01E03.zh-CN.srt
```

目录模板包含季数时，同一来源目录中的不同季可按季拆分。需要可用的父级 NFO；如果某一集的 NFO 尚未就绪或缺少文件名所需字段，可以先整理到目标目录并保留该集原文件名，待单集元数据补齐后再重命名。

### 小说与漫画示例

小说可使用：

```text
{{parent.title}}/{{title}}
```

如果 OPF 中标题为「示例小说」，原正文为 `正文.epub`，整理后为 `示例小说/示例小说.epub`。

连载漫画可使用相同模板：第一段取合集标题，第二段取各话标题。例如 `旧合集/01/正文.cbz` 可整理为 `示例漫画/第 01 话/第 01 话.cbz`。图片话则重命名话目录，保留其中的页面文件名。

需要卷号或话号时可在第二段加入对应字段，但必须先补齐该字段。独立图片漫画只重命名作品目录；合集整理要求对应阅读单元可识别、已入库且归属明确。

## 相关文件与下载转移

整理时会同步处理对应的 NFO、同名外挂字幕、弹幕缓存及可安全迁移的本地图片，并更新相关路径和 NFO 引用。视频条目会保留原有标识与播放进度；被其他媒体引用的图片不会盲目移走。

小说与漫画会同步处理外置 OPF、ComicInfo 和相关封面，更新索引与缓存引用，并保留条目标识及阅读进度。入库时记录的原始文件信息也会保留，后续整理不会把它改为整理后的名称。

[下载完成后转移](../downloads/plans#完成后转移)与自动整理分两步执行：先按下载任务的转移方式和文件名替换规则将文件放入媒体库，再根据 NFO 执行媒体库的重命名模板。仍有相关文件转移未完成时，整理会延后处理。

使用硬链接或复制入库时，库内整理不会改名或删除原下载文件。使用软链接时，整理的是库内链接，原始下载文件必须保持可访问。系统会检查下载源和其他文件引用，可能破坏引用的整理会被跳过。

## 未按模板整理时

先在**系统监控 → 系统日志**中查看对应媒体的处理记录，再按以下情况检查：

| 情况                     | 处理方式                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| 保存模板后旧文件没有变化 | 对目标条目重新刮削，或更新其 NFO 后等待监控处理                   |
| 缺少 NFO 或模板字段      | 补齐元数据，或从模板中去掉无法提供的字段                          |
| 目标文件已存在           | 检查是否有同名视频；系统不会覆盖已有文件                          |
| 目标目录已被占用         | 非空目录需具有匹配的 NFO 媒体标识才能合并，单凭标题相同不足以确认 |
| 多分段电影               | 当前没有分段命名规则，会跳过自动整理，原有入库和播放不受影响      |
| 下载尚未全部转移         | 等待相关转移完成后继续处理                                        |
| 目录或链接存在冲突       | 检查目录软链接、被其他条目引用的文件，以及媒体库与下载源路径      |
| 无写入权限或跨文件系统   | 源目录和目标目录需可写；自动整理不能跨文件系统移动文件            |

整理过程会记录待完成操作，服务重启后会先尝试恢复。若恢复被文件冲突或权限问题阻止，应先解决日志中的原因，再重试相关操作。
