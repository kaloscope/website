# 定时调度

需要定时抓取推荐榜单或周期性检查资源状态时，可以用定时调度让工作流在后台自动运行。列表里支持按名称、状态和触发方式筛选，也能随时新增、修改、暂停、恢复或删除。

## 新增任务

需要先准备好一个「定时调度」类别的工作流并发布，才能去 **设置 → 工作流 → 定时调度** 建任务。草稿状态的工作流不会出现在下拉列表里；如果已经发布过又改成了「有更新」，定时任务跑的依然是上次发布的那个版本。

### 从任务弹窗创建工作流

建任务时如果还没准备好工作流，可以直接点「工作流」选择框旁边的「新增工作流」跳到流程定义页，系统会自动打开创建弹窗并预选好「定时调度」类别。搭好流程并发布后，再回到定时调度页重新新增任务即可。

### 任务字段

新增任务时填写这些字段：

| 字段     | 必填 | 说明                                                     |
| -------- | ---- | -------------------------------------------------------- |
| 工作流   | ✓    | 选择已发布的「定时调度」工作流，任务创建后不可更换       |
| 启动参数 |      | 以 JSON 对象格式传入工作流的初始变量，默认为 `{}`        |
| 触发方式 | ✓    | 控制任务的执行时机，支持单次执行、间隔执行和 Cron 表达式 |

不同触发方式对应的附加字段：

**单次执行**

| 字段     | 必填 | 说明                 |
| -------- | ---- | -------------------- |
| 执行时间 | ✓    | 指定一次性触发的时刻 |

**间隔执行**

| 字段     | 必填 | 说明                                                       |
| -------- | ---- | ---------------------------------------------------------- |
| 间隔     | ✓    | 执行间隔，由数值和单位组成，单位支持秒、分钟、小时、天、周 |
| 开始时间 |      | 任务首次触发的最早时间，留空则从当前时刻起按间隔调度       |
| 结束时间 |      | 任务停止触发的时间，留空则持续运行                         |

**Cron 表达式**

| 字段        | 必填 | 说明                                              |
| ----------- | ---- | ------------------------------------------------- |
| Cron 表达式 | ✓    | 标准五段式格式，如 `0 * * * *` 表示每小时整点执行 |

注意：Cron 表达式一律按 **UTC** 时区解释，**不会**随容器的 `TZ` 环境变量变化。比如想让任务在北京时间每天 20:00 执行，这里应填写 `0 12 * * *`。

启动参数必须是合法的 JSON 对象，例如 `{"keyword":"示例剧集"}`。参数会直接进入工作流上下文，也可以在「开始」节点里通过 `params` 引用。

## 运行状态

任务只有「运行中」和「已暂停」两种状态：运行中的可以手动暂停，暂停后也能随时恢复。刚新建、暂停或恢复任务时，页面会在短时间内自动刷新几次列表，方便直接看到状态变化。

## 通过助手管理

也可以在对话里让 [AI 助手](../ai/assistant) 帮忙查已有定时任务，或者新建、修改、暂停、恢复和删除任务。动手前它会先把目标、时间和参数列出来等你确认；如果有多个同名任务，会先让你指定具体哪一个。

通过助手和 [MCP](../ai/mcp) 配置的调度同样按 UTC 解析 Cron。另外，任务显示创建或恢复成功只代表调度器接管了它，工作流是否执行成功，还是要查看对应的执行日志。
