# 网络设置

想让 Kaloscope 按域名走不同的代理，或者用加密 DNS 防污染？这些都可以在网络设置里统一配好。整个模块分成 **URL 规则**、**DNS 解析器**和**代理服务器**三块：你可以先建好几个可复用的解析器和代理，再通过 URL 规则把不同站点分流过去。

## 作用范围

这里的网络规则会管住 Kaloscope 服务端发出的**所有对外 HTTP 请求**，包括：

- 工作流里的 HTTP 请求节点
- GitHub API 请求
- 流程模板的 Git 仓库克隆与拉取

::: tip 注意
同步流程模板仓库（Git 操作）时，如果命中了 HTTP 代理规则，系统会通过代理环境变量走代理；不过加密 DNS 规则对 Git 命令本身不生效。
:::

## 匹配模式

每条规则的**匹配模式**都会拿去和完整的请求 URL 做 shell 风格的通配符比对（`*` 匹配任意长度字符，`?` 匹配单个字符）。如果填写的模式末尾不是 `*`，系统会自动在后面补上 `*`，也就是说直接填域名或路径前缀就能匹配底下所有地址。

| 匹配模式                   | 实际生效                    | 匹配示例                            |
| -------------------------- | --------------------------- | ----------------------------------- |
| `https://api.example.com`  | `https://api.example.com*`  | `https://api.example.com/search`    |
| `https://*.example.com/v2` | `https://*.example.com/v2*` | `https://api.example.com/v2/search` |
| `https://*`                | `https://*`                 | 匹配所有 HTTPS 请求                 |

::: tip 规则优先级
规则是从上往下依次匹配的，只要撞上第一条符合的就立刻采用并停下来。所以记得把写得更具体、范围更窄的规则放前面，把 `https://*` 这类兜底规则放最后。
:::

## DNS 解析器

支持配置 **DNS over TLS（DoT）** 和 **DNS over HTTPS（DoH）** 两种加密解析器，防止 DNS 查询被劫持或污染。

| 字段名称                                                                   | 字段类型      | 说明                                                                                                     |
| -------------------------------------------------------------------------- | ------------- | -------------------------------------------------------------------------------------------------------- |
| 名称                                                                       | 字符串        | 解析器的显示名称，全局唯一                                                                               |
| 协议                                                                       | `TLS`/`HTTPS` | 解析协议                                                                                                 |
| 域名服务器                                                                 | 字符串        | DoT 填写域名服务器 IP 地址，DoH 填写 IP 地址或完整的 HTTPS URL（如 `https://dns.example.com/dns-query`） |
| [DNSSEC](https://www.cloudflare.com/learning/dns/dnssec/how-dnssec-works/) | 布尔值        | 开启后要求服务器返回经过验证的应答，验证失败则丢弃结果                                                   |

一条规则可以同时勾选多个 DNS 解析器——查询时会并发向它们发请求，谁先返回有效结果就用谁，并且本地会缓存 6 个小时。

## 代理服务器

支持 **HTTP** 和 **SOCKS5** 两种代理协议，用来转发发往外部站点的请求。

| 字段名称 | 字段类型        | 说明                     |
| -------- | --------------- | ------------------------ |
| 名称     | 字符串          | 代理的显示名称，全局唯一 |
| 协议     | `HTTP`/`SOCKS5` | 代理类型                 |
| 主机     | 字符串          | 代理服务器地址           |
| 端口     | 整数            | 代理服务器端口           |
| 用户名   | 字符串（可选）  | 代理认证用户名           |
| 密码     | 字符串（可选）  | 代理认证密码             |

注意每条 URL 规则最多只能绑定一个代理服务器。

::: tip 代理与 DNS 的兼容性

- **HTTP 代理 + DNS**：不会同时起作用；一旦走 HTTP 代理，域名解析交给代理服务器去做，本地配的加密 DNS 会被忽略。
- **SOCKS5 代理 + DNS**：可以配合使用；系统会先用加密 DNS 把域名解析成 IP，再带着这个 IP 走 SOCKS5 代理建连。

:::
